# 13: 命名地点并创建区域提醒

**What to build:** 用户保存一个有名称的地点，选择进入或离开区域时提醒，在真机收到一次系统区域通知并能查看事项来源。

**Blocked by:** [03: 安排本地时间提醒](03-local-time-reminder.md)

**Status:** ready-for-agent

**Parent:** [Haiji v1 Engineering Specification](../spec.md)

**规格定位：** US-05、US-26–US-28、US-44、US-48；D-02、D-05、D-07、D-09–D-10、D-12；AC-07、AC-12、AC-17。引用场景按本票范围验收，不要求提前实现其他票的功能。

**交付范围：** 自签名 v1 必需范围。 手动选择明确区域即可贯通路径；不依赖尚未完成的个人记忆聊天管理。Place 使用规格的确认记忆语义与稳定身份，后续复用。

**界面依据：** [Haiji UI 设计](../../../archived/haiji-ui-design.md)。使用原生 SwiftUI，沿用父规格的可访问性与错误反馈要求。

**测试边界：** 沿用父规格 T-01/T-02：从公开 API 验证外部可见行为，使用真实 PostgreSQL/pg-boss，仅替代模型、邮箱和推送等外部服务；涉及系统通知、权限或离线的结果补充原生真机证据。新增或修改的 API 同步维护 OpenAPI 与 Swift DTO 契约。

## Acceptance criteria

- [ ] 用户确认名称和地理区域参数，服务端保存 owner 范围内的 Place 与 revision；只保存指定区域，不采集或上传轨迹。
- [ ] 创建单次 enter/exit Reminder，关联已确认 placeId、当前区域参数和固定 occurrence；本机采用 local 归属与安装回执。
- [ ] 位置权限只在需要地点提醒时请求；拒绝、系统条件不可用或容量不足时明确未安装，不虚构已就绪或服务端位置兜底。
- [ ] 界面说明系统区域检测可能延迟，不承诺出门前触发；地点事项单独展示条件，不伪造某个到期时间。
- [ ] 本地系统通知使用单次触发语义，保留稳定 requestId 与恢复日志；服务端区分安装、用户动作和观察回执，不推定通知已展示。
- [ ] 公开 API 测试覆盖 Place 归属、版本、参数及 occurrence 唯一性；真机记录实际进入/离开区域验证、后台与位置权限结果，模拟器结果不替代实测。

**完成条件：** 验收项全部通过并附可复核证据；需要外部凭据、真机或审核而尚未验证的项保持未完成。先满足所有 Blocked by，再开始实施；ready-for-agent 表示规格可实施，不表示依赖已经完成。
