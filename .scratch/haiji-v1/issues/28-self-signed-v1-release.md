# 28: 交付完整自签名 v1

**What to build:** 目标用户通过自签名 App 完成时间提醒、地点提醒和邮件建议三个完整流程，并获得通过验收的 v1 发行版本与明确的能力限制。

**Blocked by:** [08: 多轮澄清与对话修改](08-clarify-and-edit-in-conversation.md)；[19: 处理后续邮件与截止时间冲突](19-email-thread-conflicts.md)；[21: 接收每日建议摘要](21-daily-suggestion-digest.md)；[23: 导出个人数据](23-export-personal-data.md)；[24: 吊销与替换主要设备](24-revoke-and-replace-device.md)；[27: 从发行包完成自托管安装](27-self-hosted-distribution.md)

**Status:** ready-for-agent

**Parent:** [Haiji v1 Engineering Specification](../spec.md)

**规格定位：** US-01–US-61、US-63–US-64；D-01、D-10、D-14–D-15；AC-01–AC-22。引用场景按本票范围验收，不要求提前实现其他票的功能。

**交付范围：** 自签名 v1 必需范围。 这是集成和发布验收票，不承接此前票中遗漏的功能。前置关系传递覆盖 01–27；若验收暴露功能缺陷，修复并重验受影响行为后才可完成。

**界面依据：** [Haiji UI 设计](../../../archived/haiji-ui-design.md)。使用原生 SwiftUI，沿用父规格的可访问性与错误反馈要求。

**测试边界：** 沿用父规格 T-01/T-02：从公开 API 验证外部可见行为，使用真实 PostgreSQL/pg-boss，仅替代模型、邮箱和推送等外部服务；涉及系统通知、权限或离线的结果补充原生真机证据。新增或修改的 API 同步维护 OpenAPI 与 Swift DTO 契约。

## Acceptance criteria

- [ ] 核对父规格 US-01–61、US-63–64 与 AC-01–22 的自签名部分，逐项记录证据；官方中继部分留给 30，不能用本票代替官方包验收。
- [ ] 公开 API 全流程使用真实 PostgreSQL/pg-boss 和可控外部依赖，覆盖重复提交、事务失败、进程崩溃、过期、权限撤回及删除恢复；常规 CI 可重复运行。
- [ ] 至少 50 条自然交代与 50 条合成邮件形成可复现模型评估；记录版本、token/费用、正确提案/澄清率及 p50/p95。发布前根据首轮基线冻结质量/延迟门槛并达标，禁止动作和幂等不变量全部通过。
- [ ] 真机覆盖本地/远程通知、进入/离开地点、锁屏/后台/重启、离线恢复、权限拒绝/撤回、Focus 和旧通知动作；证据说明设备、系统和签名环境。
- [ ] 三个导航入口、空态、错误恢复、来源说明、深浅色、Reduce Motion/Transparency、最大字号、VoiceOver 焦点和至少 44 pt 热区均验收。
- [ ] 5–8 位目标用户完成三个核心流程，记录误操作、来源可发现性与排程状态理解问题；影响完成任务的问题在发布前修复。
- [ ] 安装与恢复演练、秘密扫描、导出/删除竞态和备份残留说明均可复核；说明 APNs 受理≠展示、区域触发可能延迟，以及离线设备清理限制。
- [ ] 交付可对应源码版本的自签名 v1 发行物、验收记录和已知限制；不把仅完成时间提醒或 HTML 演示标记为完整 v1。

**完成条件：** 验收项全部通过并附可复核证据；需要外部凭据、真机或审核而尚未验证的项保持未完成。先满足所有 Blocked by，再开始实施；ready-for-agent 表示规格可实施，不表示依赖已经完成。
