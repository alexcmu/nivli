# 27: 从发行包完成自托管安装

**What to build:** 另一位开发者按照发行文档，在干净环境部署 Haiji、配置模型/Gmail/自有 APNs，配对自签名 iPhone 并验证提醒与恢复路径。

**Blocked by:** [25: 备份恢复与安全升级](25-backup-restore-and-upgrade.md)；[26: 查看模型成本与服务健康](26-model-cost-and-service-health.md)

**Status:** ready-for-agent

**Parent:** [Haiji v1 Engineering Specification](../spec.md)

**规格定位：** US-01–US-04、US-57–US-59、US-61；D-01、D-03、D-13–D-15；AC-01、AC-19–AC-20、AC-22。引用场景按本票范围验收，不要求提前实现其他票的功能。

**交付范围：** 自签名 v1 必需范围。 复用已有业务闭环完成可安装发行物和文档。保持源码可自托管，官方中继发行包不是本票前提。

**界面依据：** [Haiji UI 设计](../../../archived/haiji-ui-design.md)。使用原生 SwiftUI，沿用父规格的可访问性与错误反馈要求。

**测试边界：** 沿用父规格 T-01/T-02：从公开 API 验证外部可见行为，使用真实 PostgreSQL/pg-boss，仅替代模型、邮箱和推送等外部服务；涉及系统通知、权限或离线的结果补充原生真机证据。新增或修改的 API 同步维护 OpenAPI 与 Swift DTO 契约。

## Acceptance criteria

- [ ] CI 构建同版本 linux/amd64 与 linux/arm64 应用镜像，锁定依赖和镜像 digest，包含 SBOM、依赖许可证信息和扫描结果。
- [ ] 生产镜像多阶段构建、非 root、只读根文件系统与受限临时目录；数据库持久化且不发布公网端口，连接入口按规格使用有效 TLS。
- [ ] 提供不含真实密钥的示例配置，文件 secret 或加密持久化策略可用，模型提供方与 APNs 开发/生产配置可验证。
- [ ] 安装说明贯通启动、配对、模型验证、Gmail 授权、真机 APNs 测试、健康诊断、升级、备份/恢复及卸载数据范围。
- [ ] iOS 编译/签名明确依赖 macOS 工具链及开发者自己的身份；需要人工取得的凭据有具体步骤，不用占位凭据宣称真机验证完成。
- [ ] 在干净部署演练配对、手动提醒、模型交代及邮箱授权路径；以真实数据库和测试外部依赖做可重复检查，另记录自签名真实推送证据。
- [ ] 根许可证由维护者明确决定后进入公开发行物，不能把规格中的 Apache-2.0 建议当成已经授权；其他依赖和模型服务的许可/计费范围分别说明。

**完成条件：** 验收项全部通过并附可复核证据；需要外部凭据、真机或审核而尚未验证的项保持未完成。先满足所有 Blocked by，再开始实施；ready-for-agent 表示规格可实施，不表示依赖已经完成。
