# 25: 备份恢复与安全升级

**What to build:** 自托管用户能将个人环境恢复到空实例或完成版本升级，重新连接后看到正确事项；未来提醒继续，已遗忘数据与过期通知不会被重新带回。

**Blocked by:** [22: 删除对话或整个个人环境](22-delete-conversation-and-environment.md)

**Status:** ready-for-agent

**Parent:** [Haiji v1 Engineering Specification](../spec.md)

**规格定位：** US-01、US-48、US-56、US-58、US-64；D-03、D-07–D-09、D-13–D-14；AC-08、AC-11、AC-18–AC-19。引用场景按本票范围验收，不要求提前实现其他票的功能。

**交付范围：** 自签名 v1 必需范围。 验证应用生命周期已有能力，不重新开发提醒或删除逻辑。RPO/RTO 是要测量的目标，不直接宣称已经达到。

**界面依据：** [Haiji UI 设计](../../../archived/haiji-ui-design.md)。使用原生 SwiftUI，沿用父规格的可访问性与错误反馈要求。

**测试边界：** 沿用父规格 T-01/T-02：从公开 API 验证外部可见行为，使用真实 PostgreSQL/pg-boss，仅替代模型、邮箱和推送等外部服务；涉及系统通知、权限或离线的结果补充原生真机证据。新增或修改的 API 同步维护 OpenAPI 与 Swift DTO 契约。

## Acceptance criteria

- [ ] 提供每日加密离机备份及默认 7 日保留策略，说明数据库、加密主密钥与独立最小删除清单的保存和恢复关系。
- [ ] 从备份恢复到空环境后，开放 API/worker 前必须应用最新删除清单/epoch；不能仅恢复数据库就恢复已撤回的读取与投递。
- [ ] 未来 Reminder 可重新物化，恢复保留原 occurrence 身份、归属和 unknown 结果；超窗提醒不批量补发，本机归属不被自动接管。
- [ ] 客户端重新连接后按 snapshot/changes 获得一致状态；被删除对象、旧授权与失效会话不因旧备份复活。
- [ ] 升级流程先备份并在恢复副本上验证迁移，执行互斥的单次迁移后启动兼容 worker；迁移失败有诊断，不删除数据卷解决问题。
- [ ] 记录实际测试数据规模、RPO/RTO、恢复步骤和失败处理，检验 RPO≤24 小时、RTO≤1 小时目标；未达标保留测量结果并修复。
- [ ] 以公开 API 创建未来计划和待删数据，备份→删除→恢复→再读取/到期验证，使用真实 PostgreSQL/队列；原生客户端验证恢复后的事项与排程状态。

**完成条件：** 验收项全部通过并附可复核证据；需要外部凭据、真机或审核而尚未验证的项保持未完成。先满足所有 Blocked by，再开始实施；ready-for-agent 表示规格可实施，不表示依赖已经完成。
