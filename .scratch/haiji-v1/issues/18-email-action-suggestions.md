# 18: 邮件生成行动建议

**What to build:** 授权范围内的一封邮件生成有发件人、日期和依据片段的待确认建议；用户编辑接受后才安排提醒，并能完成该事项。

**Blocked by:** [17: 连接 Gmail 与控制读取范围](17-gmail-connect-and-sync.md)；[16: 从记忆关联生成建议](16-memory-backed-suggestions.md)

**Status:** ready-for-agent

**Parent:** [Haiji v1 Engineering Specification](../spec.md)

**规格定位：** US-17、US-19、US-31、US-33–US-37、US-57；D-04–D-07、D-10、D-12；AC-05、AC-13–AC-14、AC-16。引用场景按本票范围验收，不要求提前实现其他票的功能。

**交付范围：** 自签名 v1 必需范围。 复用 Pi adapter 与 Suggestion 确认命令。首版只处理必要邮件正文片段，后续线程变化由 19 扩展。

**界面依据：** [Haiji UI 设计](../../../archived/haiji-ui-design.md)。使用原生 SwiftUI，沿用父规格的可访问性与错误反馈要求。

**测试边界：** 沿用父规格 T-01/T-02：从公开 API 验证外部可见行为，使用真实 PostgreSQL/pg-boss，仅替代模型、邮箱和推送等外部服务；涉及系统通知、权限或离线的结果补充原生真机证据。新增或修改的 API 同步维护 OpenAPI 与 Swift DTO 契约。

## Acceptance criteria

- [ ] 同步事件触发受限 Pi 提取；消息/内容身份稳定，重复同步或 worker 重启不会生成同候选的重复建议。
- [ ] 邮件属于不可信输入，只能产生 pending proposal；shell、任意 URL、附件执行、密钥访问和直接完成任务都没有可用能力。
- [ ] 提取仅使用授权范围内必要字段和正文片段；营销、转发引文或已读状态不能被当成用户承诺。
- [ ] 建议展示发件人、日期、简短证据和待确认标记，用户编辑最终提醒条件后接受；事务、版本与撤销复用 16。
- [ ] 候选需要澄清时保留不确定字段；未经用户接受无正式任务和任务通知。接受后可通过既有时间提醒与完成路径跑通。
- [ ] 默认正文缓存 7 天，可配置更短；证据摘要的保留区别于原文，来源页能说明原文已经清理。
- [ ] 公开 API/真实队列测试贯通合成邮件→建议→编辑接受→提醒→完成，并验证注入、越权、重复消费和授权变化的无副作用结果。
- [ ] 建立至少 50 条合成邮件评估样本，覆盖中英文、日期歧义、重复/冲突和注入；真实模型评估记录版本、usage、费用及正确提案/澄清结果，不使用私人邮件作默认测试数据。

**完成条件：** 验收项全部通过并附可复核证据；需要外部凭据、真机或审核而尚未验证的项保持未完成。先满足所有 Blocked by，再开始实施；ready-for-agent 表示规格可实施，不表示依赖已经完成。
