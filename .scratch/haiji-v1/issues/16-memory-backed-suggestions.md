# 16: 从记忆关联生成建议

**What to build:** 用户交代一次见面安排时，Haiji 可关联已确认的借书信息，提出归还建议；用户编辑接受后才形成事项，或忽略并撤销误操作。

**Blocked by:** [15: 确认、纠正与遗忘个人记忆](15-personal-memory-controls.md)；[04: 完成、推迟、取消与撤销](04-task-actions-and-undo.md)

**Status:** ready-for-agent

**Parent:** [Haiji v1 Engineering Specification](../spec.md)

**规格定位：** US-17、US-19、US-21、US-25、US-34–US-35、US-40–US-41、US-47；D-02、D-04–D-07、D-10、D-12；AC-05–AC-06、AC-14–AC-16。引用场景按本票范围验收，不要求提前实现其他票的功能。

**交付范围：** 自签名 v1 必需范围。 建立可复用 Suggestion 的完整确认路径，首个真实来源为用户记忆关联。邮箱输入在 18 接入，不用虚构数据源替代本票的端到端验收。

**界面依据：** [Haiji UI 设计](../../../archived/haiji-ui-design.md)。使用原生 SwiftUI，沿用父规格的可访问性与错误反馈要求。

**测试边界：** 沿用父规格 T-01/T-02：从公开 API 验证外部可见行为，使用真实 PostgreSQL/pg-boss，仅替代模型、邮箱和推送等外部服务；涉及系统通知、权限或离线的结果补充原生真机证据。新增或修改的 API 同步维护 OpenAPI 与 Swift DTO 契约。

## Acceptance criteria

- [ ] 给定确认的借书事实和新的见面输入，只产生带依据的 pending 建议，不能将模型联想直接写成正式任务。
- [ ] 首页“待你确认”与正式事项分组，建议没有完成按钮；详情可查看来源、推测动作与原始依据。
- [ ] 接受进入可编辑表单，提交最终条件及 suggestion revision；事务校验 pending、来源有效性和目标版本，创建或更新任务并关联 acceptedTaskId。
- [ ] 重复或并发接受返回同一逻辑结果；dismissed/superseded、旧目标版本或遗忘来源不能被旧请求无提示接受。
- [ ] 忽略只影响该建议，undo-dismiss 在来源有效且未替代时恢复；撤销接受仅在任务无后续变化时取消新增事项或恢复先前字段。
- [ ] 接受后的事项通过已有路径安排提醒和处理完成；不响应不追加打扰、提高紧急程度或改变长期偏好。
- [ ] 公开 API/真实事务测试贯通记忆→新输入→建议→接受→任务，覆盖回滚、并发、过期依据及撤销冲突；SwiftUI 验证编辑接受、忽略和来源查看。

**完成条件：** 验收项全部通过并附可复核证据；需要外部凭据、真机或审核而尚未验证的项保持未完成。先满足所有 Blocked by，再开始实施；ready-for-agent 表示规格可实施，不表示依赖已经完成。
