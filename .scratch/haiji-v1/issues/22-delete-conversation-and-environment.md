# 22: 删除对话或整个个人环境

**What to build:** 用户选择删除对话或整个个人环境后，应用说明并执行相应范围的清理，阻断继续读取和回灌，分别展示服务器、当前设备及备份状态。

**Blocked by:** [20: 断开邮箱与清理衍生数据](20-gmail-disconnect-and-purge.md)；[14: 地点变更与时间替代](14-place-changes-and-time-fallback.md)；[11: 同步缺口与全量恢复](11-sync-snapshot-recovery.md)；[09: 模型失败、取消与预算恢复](09-agent-failure-budget-and-cancel.md)

**Status:** ready-for-agent

**Parent:** [Haiji v1 Engineering Specification](../spec.md)

**规格定位：** US-42–US-43、US-49、US-55–US-57、US-63；D-05、D-07、D-09、D-11–D-13；AC-10–AC-11、AC-16、AC-18。引用场景按本票范围验收，不要求提前实现其他票的功能。

**交付范围：** 自签名 v1 必需范围。 复用邮箱、记忆、地点和同步已有的删除屏障，不重新实现其业务逻辑。导出与删除竞态由 23 接入同一 deletion epoch，备份恢复由 25 接入删除清单。

**界面依据：** [Haiji UI 设计](../../../archived/haiji-ui-design.md)。使用原生 SwiftUI，沿用父规格的可访问性与错误反馈要求。

**测试边界：** 沿用父规格 T-01/T-02：从公开 API 验证外部可见行为，使用真实 PostgreSQL/pg-boss，仅替代模型、邮箱和推送等外部服务；涉及系统通知、权限或离线的结果补充原生真机证据。新增或修改的 API 同步维护 OpenAPI 与 Swift DTO 契约。

## Acceptance criteria

- [ ] 不可恢复删除前展示明确范围；对话删除说明关联原文与派生摘要处理，不能默认把保留的确认记忆也伪装成已删除。
- [ ] 整环境删除先阻断新读写并提升 data/deletion epoch，再处理任务、提醒、来源、证据、建议、记忆、会话派生数据、队列引用与临时生成物；旧 run 晚到不能写回。
- [ ] 删除 job 提供范围、进度、失败和可重试结果；先确认受限的删除进度查询方式，再吊销普通会话，不能让用户删除后无法区分完成与失败。
- [ ] 当前设备清理私有投影、草稿/outbox、相关系统通知与凭据；离线删除先本机清理并显示待同步，服务端完成前不显示服务器已删除。
- [ ] 停止服务端未来投递和来源读取，撤销推送绑定；其他设备离线副本/既有展示分别报告待确认或不可立即撤回。
- [ ] 删除使用最小抑制标记、持久 tombstone 与独立删除清单，防止旧投影、旧会话提取或较旧备份自动恢复内容；清单不保存被删正文。
- [ ] 默认备份最多保留 7 日残留，范围确认及完成页面准确说明；失败重试不恢复已阻断的访问。
- [ ] 公开 API/真实队列测试并发删除和迟到 run、部分清理失败、旧客户端重放及会话吊销；设备验收本机通知清理、离线删除和状态恢复。

**完成条件：** 验收项全部通过并附可复核证据；需要外部凭据、真机或审核而尚未验证的项保持未完成。先满足所有 Blocked by，再开始实施；ready-for-agent 表示规格可实施，不表示依赖已经完成。
