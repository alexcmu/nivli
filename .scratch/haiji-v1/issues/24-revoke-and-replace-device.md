# 24: 吊销与替换主要设备

**What to build:** 用户可以撤销旧设备访问，再为替换的主要 iPhone 配对；新设备恢复当前事项，界面明确旧设备本地提醒可能仍需清理。

**Blocked by:** [11: 同步缺口与全量恢复](11-sync-snapshot-recovery.md)

**Status:** ready-for-agent

**Parent:** [Haiji v1 Engineering Specification](../spec.md)

**规格定位：** US-03–US-04、US-48、US-50–US-51、US-56、US-63；D-05、D-07、D-09、D-11、D-13–D-14；AC-01、AC-07、AC-11、AC-18。引用场景按本票范围验收，不要求提前实现其他票的功能。

**交付范围：** 自签名 v1 必需范围。 首版保持一个主要 iPhone。吊销后拒绝业务访问是硬约束，但服务器无法保证即时抹除离线设备或撤回已显示通知。

**界面依据：** [Haiji UI 设计](../../../archived/haiji-ui-design.md)。使用原生 SwiftUI，沿用父规格的可访问性与错误反馈要求。

**测试边界：** 沿用父规格 T-01/T-02：从公开 API 验证外部可见行为，使用真实 PostgreSQL/pg-boss，仅替代模型、邮箱和推送等外部服务；涉及系统通知、权限或离线的结果补充原生真机证据。新增或修改的 API 同步维护 OpenAPI 与 Swift DTO 契约。

## Acceptance criteria

- [ ] 受保护管理入口可吊销指定 device/session，并失效其 APNs 绑定；旧凭据的读取、写入、同步、导出和通知动作全部拒绝。
- [ ] 替换设备先走当前有效的一次性配对与主机确认，明确新的主要设备身份，不默认开启两台主设备同时提醒。
- [ ] 新设备先拉取一致 snapshot，再确认系统权限与推送身份并安排当前计划；不能把旧设备本地状态当作新机已安装。
- [ ] 旧设备 server-owned 未发送实例失效；旧 local 计划的清理能力与结果明确区分，旧设备不可达时不宣称已撤回。
- [ ] 旧设备重新联网发现吊销后停止同步，按可执行范围清理私有投影和系统请求；不重放旧 outbox 覆盖新主设备决策。
- [ ] 公开 API 测试从配对→使用→吊销→所有旧能力被拒→新设备配对/恢复；真机记录替换后的权限、当前计划及旧设备清理限制。

**完成条件：** 验收项全部通过并附可复核证据；需要外部凭据、真机或审核而尚未验证的项保持未完成。先满足所有 Blocked by，再开始实施；ready-for-agent 表示规格可实施，不表示依赖已经完成。
