# 20: 断开邮箱与清理衍生数据

**What to build:** 用户可独立停止邮箱读取，或进一步删除邮箱产生的信息并选择是否保留已确认事项；界面清楚展示清理范围和结果。

**Blocked by:** [18: 邮件生成行动建议](18-email-action-suggestions.md)

**Status:** ready-for-agent

**Parent:** [Nivli v1 Engineering Specification](../spec.md)

**规格定位：** US-31、US-39、US-42、US-56–US-57；D-05、D-07、D-10、D-12–D-13；AC-13、AC-16、AC-18。引用场景按本票范围验收，不要求提前实现其他票的功能。

**交付范围：** 自签名 v1 必需范围。 在 17 的授权屏障上加入完整衍生数据生命周期，为整体删除复用。基础最小删除清单在这里记录，备份恢复应用由 25 验证。

**界面依据：** [Nivli UI 设计](../../../archived/nivli-ui-design.md)。使用原生 SwiftUI，沿用父规格的可访问性与错误反馈要求。

**测试边界：** 沿用父规格 T-01/T-02：从公开 API 验证外部可见行为，使用真实 PostgreSQL/pg-boss，仅替代模型、邮箱和推送等外部服务；涉及系统通知、权限或离线的结果补充原生真机证据。新增或修改的 API 同步维护 OpenAPI 与 Swift DTO 契约。

## Acceptance criteria

- [ ] 停止读取立即撤销 connector 能力、提升授权版本并取消新同步；需要执行提供方撤销时记录其结果。已确认任务默认保持可用。
- [ ] 删除衍生数据前列出原文、片段、摘要、检索、会话派生关联和建议范围，并让用户明确是否保留已确认任务。
- [ ] 选择保留任务时保留用户确认的行动内容，清除选定邮箱原文、摘要、索引和生成关联；来源展示已移除，不伪装仍可访问。
- [ ] 删除先阻断读取和晚到写回，再异步清理；进度、失败和重试通过公开 API 与设置界面可查看，不以隐藏 UI 代替清理。
- [ ] 授权撤回或删除发生在 Gmail/模型执行中时，旧版本结果不能回灌；保留不含正文的必要抑制身份防止重同步再生。
- [ ] 若选择取消相关任务，走已有事项/通知命令并记录设备清理待确认；不能承诺立即清除离线设备副本。
- [ ] 删除产生可持久恢复的最小删除清单/epoch，清单独立于普通备份且不包含被删正文；备份残留窗口有准确说明。
- [ ] 公开 API 测试覆盖 stop 与 purge 区别、保留/不保留事项、晚到返回、重同步及部分清理失败；界面提供范围确认和可执行重试。

**完成条件：** 验收项全部通过并附可复核证据；需要外部凭据、真机或审核而尚未验证的项保持未完成。先满足所有 Blocked by，再开始实施；ready-for-agent 表示规格可实施，不表示依赖已经完成。
