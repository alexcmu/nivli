# 30: 交付官方 App 分发路径

**What to build:** 用户安装官方签名构建后，按公开说明连接自己的环境、授权邮箱与中继，完成提醒流程并能撤回授权；官方分发所需条件均有证据。

**Blocked by:** [28: 交付完整自签名 v1](28-self-signed-v1-release.md)；[29: 绑定和撤销官方推送中继](29-official-push-relay.md)

**Status:** ready-for-agent

**Parent:** [Nivli v1 Engineering Specification](../spec.md)

**规格定位：** US-01、US-04、US-31、US-44、US-46、US-57、US-61–US-63；D-01、D-12–D-15；AC-01、AC-13、AC-17–AC-18、AC-22。引用场景按本票范围验收，不要求提前实现其他票的功能。

**交付范围：** 官方分发条件阶段 M5；不阻塞自签名 v1。 条件阶段 M5。官方包的发行前验收与分发就绪工作，不以自签名结果代替官方身份验证，也不在没有授权/必要账号时擅自提交商店。

**界面依据：** [Nivli UI 设计](../../../archived/nivli-ui-design.md)。使用原生 SwiftUI，沿用父规格的可访问性与错误反馈要求。

**测试边界：** 沿用父规格 T-01/T-02：从公开 API 验证外部可见行为，使用真实 PostgreSQL/pg-boss，仅替代模型、邮箱和推送等外部服务；涉及系统通知、权限或离线的结果补充原生真机证据。新增或修改的 API 同步维护 OpenAPI 与 Swift DTO 契约。

## Acceptance criteria

- [ ] 官方包通过自己的 Team/Bundle ID/APNs 环境验证，覆盖可见任务通知和建议摘要；仅使用绑定授权过的设备，不复用开发自签名证明。
- [ ] 官方 App 连接用户自托管环境、配对、Gmail 授权、建议接受、提醒处理和导出/删除均完成端到端回归。
- [ ] 中继绑定/吊销、频率限制、通用 payload、关闭中继后的状态及本地计划行为在正式分发配置验证。
- [ ] 核实并完成当前所选 Gmail OAuth 公开分发路径要求；回调地址、scope、用户范围与实际发行方式一致，所需外部审核不能以测试账号授权成功替代。
- [ ] App 内连接说明、隐私说明与发行元数据一致披露 backend、模型服务、Gmail、Apple 及官方中继的数据流和撤回方式。
- [ ] 记录官方包真实设备、签名环境、外部审核/账户条件与验收结果；尚未满足的外部门槛准确标为未完成，不宣布官方远程通知能力已完整交付。
- [ ] 交付官方分发就绪构建和发布证据，保留自托管与自签名路径；实际商店提交按用户明确授权执行。

**完成条件：** 验收项全部通过并附可复核证据；需要外部凭据、真机或审核而尚未验证的项保持未完成。先满足所有 Blocked by，再开始实施；ready-for-agent 表示规格可实施，不表示依赖已经完成。
