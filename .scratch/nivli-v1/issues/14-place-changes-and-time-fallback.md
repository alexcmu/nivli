# 14: 地点变更与时间替代

**What to build:** 用户修改或删除地点、撤回位置权限时，能看见受影响提醒，并将无法工作的区域条件改为明确时间条件。

**Blocked by:** [13: 命名地点并创建区域提醒](13-named-place-reminder.md)；[04: 完成、推迟、取消与撤销](04-task-actions-and-undo.md)

**Status:** ready-for-agent

**Parent:** [Nivli v1 Engineering Specification](../spec.md)

**规格定位：** US-22、US-26、US-28–US-30、US-51；D-05–D-07、D-09–D-10、D-12；AC-06、AC-12。引用场景按本票范围验收，不要求提前实现其他票的功能。

**交付范围：** 自签名 v1 必需范围。 复用现有任务动作与地点计划；本票负责受影响计划处理，不将地点删除等同于删除全部关联事项。

**界面依据：** [Nivli UI 设计](../../../archived/nivli-ui-design.md)。使用原生 SwiftUI，沿用父规格的可访问性与错误反馈要求。

**测试边界：** 沿用父规格 T-01/T-02：从公开 API 验证外部可见行为，使用真实 PostgreSQL/pg-boss，仅替代模型、邮箱和推送等外部服务；涉及系统通知、权限或离线的结果补充原生真机证据。新增或修改的 API 同步维护 OpenAPI 与 Swift DTO 契约。

## Acceptance criteria

- [ ] 修改或删除 Place 前列出受影响的 active Reminder；变更提升版本并使旧区域条件失效，关联事项保持可解释的需配置状态。
- [ ] 取消旧本机区域请求有恢复日志与回执；离线或取消结果不明时准确展示清理待确认，不声称服务器已撤回系统请求。
- [ ] 拒绝或撤回位置权限后显示可执行替代入口；用户确认具体日期/时间后更新为 time Reminder，并保留 taskId、来源与独立 deadline。
- [ ] 时间替代不会同时留下有效区域和时间计划；旧 region 回执或通知动作不能覆盖新 revision。
- [ ] 用户仍能完成、取消或查看受影响事项；只读打开旧区域通知展示当前状态，权限恢复不自动恢复未经确认的旧安排。
- [ ] 公开 API 测试贯通地点变更→影响列表→时间替代与并发冲突；真机验证权限撤回、旧请求取消及新的时间通知。

**完成条件：** 验收项全部通过并附可复核证据；需要外部凭据、真机或审核而尚未验证的项保持未完成。先满足所有 Blocked by，再开始实施；ready-for-agent 表示规格可实施，不表示依赖已经完成。
