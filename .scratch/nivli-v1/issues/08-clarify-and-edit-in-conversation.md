# 08: 多轮澄清与对话修改

**What to build:** 用户能回答时间或对象澄清，继续说“改成九点半”，并看到对应事项的最新安排；跨时区、DST 和陈旧聊天卡不会产生错误修改。

**Blocked by:** [07: 用 Pi 创建明确时间提醒](07-pi-create-reminder.md)；[04: 完成、推迟、取消与撤销](04-task-actions-and-undo.md)

**Status:** ready-for-agent

**Parent:** [Nivli v1 Engineering Specification](../spec.md)

**规格定位：** US-08–US-10、US-14–US-15、US-19、US-24；D-04–D-07、D-10；AC-02–AC-03、AC-06、AC-09。引用场景按本票范围验收，不要求提前实现其他票的功能。

**交付范围：** 自签名 v1 必需范围。 复用已有 Pi run 与确定性事项命令，持久保存会话关联。一般安静时段设置由 12 交付，本票提供明确夜间时间的澄清/确认能力。

**界面依据：** [Nivli UI 设计](../../../archived/nivli-ui-design.md)。使用原生 SwiftUI，沿用父规格的可访问性与错误反馈要求。

**测试边界：** 沿用父规格 T-01/T-02：从公开 API 验证外部可见行为，使用真实 PostgreSQL/pg-boss，仅替代模型、邮箱和推送等外部服务；涉及系统通知、权限或离线的结果补充原生真机证据。新增或修改的 API 同步维护 OpenAPI 与 Swift DTO 契约。

## Acceptance criteria

- [x] 澄清回答产生关联的新 input/run，保留原始上下文和明确实体身份；近期相关历史有界，缺失信息时追问而非编造记忆。
- [x] conversation revision 串行提交；连续输入按顺序处理，后续修改针对最近有效业务结果，不能依赖进程内未保存会话。
- [x] 覆盖“晚点”、无确定上下文的周五、多任务指代，以及 DST 不存在/重复时间；明确前不生成确定提醒。
- [x] 单次固定时间保留原时区表达并存 UTC instant；旅行不移动既有时间。随当地时间变化的意图要求用户选定时区或新时间。
- [x] 自然语言修改复用 expectedRevision 和命令身份；已完成/取消任务不能被旧对话恢复，冲突保留用户原话并提供当前状态。
- [x] 聊天历史与旧确认卡关联当前实体，展示最新已更新/已完成/已取消状态；来源与具体日期可查看。
- [x] 公开 API 测试贯通澄清回答、连续修改、重启会话恢复和版本冲突；建立至少 50 条中英文交代评估样本，标注正确结果、必须澄清和禁止动作，包含 DST 与指代。
- [ ] 原生界面验证多轮消息、错误恢复、中文输入法和最大字号；真实模型评估记录版本、预算与结果，不由随机模型调用阻塞常规 CI。

**完成条件：** 验收项全部通过并附可复核证据；需要外部凭据、真机或审核而尚未验证的项保持未完成。先满足所有 Blocked by，再开始实施；ready-for-agent 表示规格可实施，不表示依赖已经完成。
