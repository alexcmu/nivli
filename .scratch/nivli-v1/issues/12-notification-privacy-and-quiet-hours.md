# 12: 通知预览与安静时段

**What to build:** 用户在“我的”设置通知预览和安静时段；明确的夜间提醒须确认，隐私切换会更新本机待发内容，系统设置限制被准确说明。

**Blocked by:** [04: 完成、推迟、取消与撤销](04-task-actions-and-undo.md)；[07: 用 Pi 创建明确时间提醒](07-pi-create-reminder.md)

**Status:** ready-for-agent

**Parent:** [Nivli v1 Engineering Specification](../spec.md)

**规格定位：** US-14、US-44–US-47、US-53；D-06–D-07、D-09–D-10；AC-17、AC-21。引用场景按本票范围验收，不要求提前实现其他票的功能。

**交付范围：** 自签名 v1 必需范围。 本票实现偏好持久化和本地/交代行为；每日建议摘要由 21 消费这些偏好。远程通知 v1 始终通用。

**界面依据：** [Nivli UI 设计](../../../archived/nivli-ui-design.md)。使用原生 SwiftUI，沿用父规格的可访问性与错误反馈要求。

**测试边界：** 沿用父规格 T-01/T-02：从公开 API 验证外部可见行为，使用真实 PostgreSQL/pg-boss，仅替代模型、邮箱和推送等外部服务；涉及系统通知、权限或离线的结果补充原生真机证据。新增或修改的 API 同步维护 OpenAPI 与 Swift DTO 契约。

## Acceptance criteria

- [ ] 偏好通过带 revision 的公开 API 保存并同步，包含安静时段、时区、建议频率与本地详情预览；旧版本修改返回冲突。
- [ ] 默认安静时段 22:00–08:00，默认建议仅应用内；显式提醒落在该时段时先进入需确认，用户继续后才按指定时间安排。
- [ ] 确认夜间提醒不改动 iOS Focus 或系统通知设置，系统权限关闭时仍如实显示未就绪。
- [ ] 默认通用文案不含标题、发件人、片段或地点；详细预览明确仅适用于本地通知，不能以一个开关暗示远程也支持。
- [ ] 详细切换为保守后重建本机 pending requests 并清理应用可移除的已投递通知；崩溃后可恢复差异，不承诺追溯撤回已显示内容。
- [ ] 偏好修改不改变 deadline、不完成事项；一次忽略不能改变长期偏好或升级通知。
- [ ] 公开 API 测试覆盖版本冲突、跨午夜时段和确认行为；真机验证锁屏文案切换、Focus/权限关闭下的界面说明，设置项支持 VoiceOver 与最大字号。

**完成条件：** 验收项全部通过并附可复核证据；需要外部凭据、真机或审核而尚未验证的项保持未完成。先满足所有 Blocked by，再开始实施；ready-for-agent 表示规格可实施，不表示依赖已经完成。
