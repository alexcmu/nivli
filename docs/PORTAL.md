# 用 Portal 测试远程通知

## 页面已经打开时

1. 打开本机的 <http://127.0.0.1:4325/portal>。
2. 若出现登录框，打开项目里的 `.secrets/portal-local.env`，复制 `ADMIN_SECRET=` 后面的值，粘贴到“管理员密钥”，点击“进入工作台”。这是后端管理密钥，不是 Apple 的 `.p8` 文件。
3. 看“选择设备”。如果设备显示“已注册 · 通知已允许”，点击“发送测试通知”。
4. 在 iPhone 通知中心查看“Haiji 测试通知”。测试不会创建事项。
5. 看页面下方的测试记录。“Apple 已受理”表示 Apple 收下了请求，不保证手机已展示；专注模式和网络也会影响展示。

## 页面提示没有设备时

1. 点击“连接新设备”。
2. 在 iPhone 打开 Haiji → 我的 → 环境连接，输入 Portal 显示的服务器地址和配对码，然后确认。
3. 到 我的 → 远程通知，点击“启用或重新注册远程通知”，允许系统通知。
4. 回到 Portal 点击“刷新状态”，再点击“发送测试通知”。

手机必须能访问服务器的 HTTPS 地址。本机网页的 `127.0.0.1` 只供 Mac 管理，不能填写到手机。纯本机启动默认显示 `https://localhost:4325`；要连接真机，先给本机后端配置 HTTPS 入口，并用 `PUBLIC_URL` 指定它。不要使用与此本机后端无关的云端服务地址。

## 页面打不开时（开发者）

1. 启动本机 PostgreSQL，在 `.secrets/portal-local.env` 配置 `DATABASE_URL`。请使用专用开发数据库。
2. APNs 配置沿用 `.secrets/apns.env`。该文件不提交 Git。
3. 在项目目录运行 `npm run portal:local`。
4. 浏览器打开终端打印的 Portal 地址。首次未配置管理密钥时，启动器自动生成并写入 `.secrets/portal-local.env`。

启动器会执行正式数据库迁移，并启动 API、agent 和远程 delivery worker。没有模型配置时仍可测试推送。修改服务器地址、数据库或端口后，重启启动器。

## 结果怎么处理

- Apple 已受理：在手机通知中心检查；未显示时先查权限和专注模式。
- 发送失败：页面显示 Apple 的错误类型；设备注册失效时在 App 重新注册。
- 结果未知：可能已经发出，不自动重发。先检查手机，再决定是否发起新的测试。
- 事项提醒记录：查看真正事项的等待、受理、失败或过期状态。App 的手动和 AI 提醒都只走远程路径。
