# 使用地点提醒

地点提醒由 iPhone 检测范围变化，再通过你的后端发送远程通知。需要手机联网、后台 App 刷新、“始终”定位和精确位置权限；不会安排本地通知，也不会持续上传位置轨迹。

## 第一步 保存家或公司

1. 打开 Haiji → 我的 → 我的地点。
2. 点击“添加地点”，名称填写“公司”或“家”。
3. 搜索地址并选择结果，或者移动地图，把十字对准地点中心。只有点击“使用当前位置作为中心”才会请求当前定位。
4. 选择范围半径，初次可用 200 米；允许范围为 100–1000 米。
5. 检查名称、地图中心和范围，勾选“我已核对名称、中心与范围”，点击“保存地点”。

保存的内容是你确认的区域，不是移动轨迹。

## 第二步 创建提醒

手动方式：

1. 在“此刻”点击“新增事项”，输入“报销”或“带快递”。
2. 在“提醒条件”中启用提醒，将“提醒方式”选为“地点”。
3. 选择已保存地点，再选择“到达时”或“离开时”。
4. 如果也希望在 22:00–08:00 提醒，明确开启“安静时段也允许此提醒”。
5. 保存事项。

自然语言方式：保存地点后，在“交代”输入“到公司提醒我报销”或“离开家提醒我带快递”。AI 只能引用已确认的地点；找不到地点时不会猜地址。地点与截止时间等组合表达尚不自动创建，可用手动表单分别填写。

## 第三步 允许后台监测

1. 打开 我的 → 地点监测与权限。
2. 点击“启用或重新检查地点监测”。按系统提示先允许使用期间定位；随后在系统设置中将 Haiji 的定位权限选为“始终”，并开启精确位置。
3. 在系统设置中确认 Haiji 的后台 App 刷新可用。
4. 返回 Haiji，再点一次“启用或重新检查地点监测”。
5. 检查事项详情：显示“正在监测地点范围”才表示已收到系统监测成功回执。还需在 我的 → 远程通知 中启用远程通知。

不想允许定位时，可以在事项详情点击“选择提醒时间”，把同一事项改成时间提醒。标题、来源和独立截止时间会保留。

## 第四步 实际进出范围

到达提醒需要从范围外进入；离开提醒需要从范围内离开。创建时已经在范围内，不等于刚刚进入。尽量走出范围后再完整跨过边界，并保持网络连接。

系统区域检测可能延迟，不保证过门口立刻弹出，更不能保证在出门前提醒。需要准时处理的事项应使用时间提醒。

离线事件使用固定操作标识保存在手机上，在 App 再次运行或系统允许后台执行时重试；仅在发生后的 15 分钟内仍可发送，过期不会补发。Apple 已受理不代表通知一定展示，通知权限和专注模式仍会影响显示。

## 修改或删除地点

1. 进入 我的 → 我的地点，点开要修改的地点。
2. 修改名称或范围并重新核对，点击保存；删除则点击“删除地点”。
3. 查看受影响的进行中事项列表，再确认。
4. 这些事项会保留，但旧地点条件失效。到事项详情重新选择地点并确认，或者改成时间提醒。

离线手机可能尚未清理旧监测；后端会拒绝旧版本事件，不会因此再发送一条通知。权限撤回会暂停监测，恢复权限后需要手动重新启用。

## 开发验证边界

后端公开 API 和真实 PostgreSQL/pg-boss 测试覆盖地点归属、版本、范围、同名冲突、重复事件、旧事件、地点修改与删除、权限回执、时间替代、恢复与迁移；APNs 使用可控替代物。Swift 测试覆盖事件持久化、重开后去重、上传字段和创建命令。

物理 iPhone 的真实进出、后台唤醒延迟及系统权限撤回仍需实地验证；编译、API 事件注入和界面检查不替代这一验证。

实现采用 Core Location 区域监测，保守使用最多 16 个范围；系统监测失败、精确位置不足、后台刷新关闭或容量不足时不显示就绪。仅用户确认的区域参数保存在后端；事件上报只有计划 ID、版本、进入或离开、事件时间，无坐标。

Apple 参考：[区域监测](https://developer.apple.com/documentation/corelocation/monitoring-the-user-s-proximity-to-geographic-regions)、[定位授权](https://developer.apple.com/documentation/corelocation/requesting-authorization-to-use-location-services)、[监测 API 与系统数量限制](https://developer.apple.com/documentation/corelocation/cllocationmanager/startmonitoring(for:))。
